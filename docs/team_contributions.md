# Реальный вклад команды

Не создавать коммиты от чужого имени и не менять даты для видимости прошлой работы. Плановая ответственность по роли не заменяет подтверждение фактического вклада.

Каждый участник берёт задачу, выполняет анализ/реализацию/проверку, фиксирует изменения под собственной учётной записью и способен объяснить результат. Заимствованный материал обозначается как заимствованный; переработка и новые проверки описываются отдельно.

| Задача | Содержательный результат | Исполнитель | Свидетельство / проверяющий |
|---|---|---|---|
| WP-01 Требования, backlog и защита | Сценарии, критерии приёмки, план спринтов, документация и презентация | Роман Садчиков — Тимлид / Scrum-мастер + Product Owner | ссылки на issue/commit и review команды |
| WP-02 Данные | Manifest, лицензии, аудит утечек и воспроизводимость сплитов | Кирилл Близнюков — MLOps / DevOps | отчёт аудита и review Романа |
| WP-03 Знания | Версионирование правил и организация экспертной проверки | Роман Садчиков — Product Owner | протокол консультанта и review Даниила |
| WP-04 Модели и эксплуатация | Воспроизводимая оценка, Docker, CI/CD и мониторинг | Кирилл Близнюков — MLOps / DevOps | pipeline CI и отчёт запуска |
| WP-05 API и интеграция | FastAPI, валидация, логирование, контракт результата | Даниил Козлов — Backend | тесты API и review Кирилла |
| WP-06 UI и визуализация | Streamlit, визуализация масок/метрик и демонстрационный сценарий | Игорь Рыженков — Frontend / Визуализатор | UI-сценарий и review Романа |
| WP-07 Приёмка и релиз | Матрица прослеживаемости, релизный чек-лист и демонстрация | Роман Садчиков координирует; каждый защищает свою часть | ссылки на коммиты участников и протокол защиты |

Это пакеты работ, а не семь ролей LMS: команда использует только четыре назначенные роли. Запись вклада: задача → конкретное изменение/эксперимент → ссылка на коммит/отчёт → review → краткое объяснение участником.
