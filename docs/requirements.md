# Требования

Статус реализации фиксируется в матрице прослеживаемости. Численные целевые значения качества и времени устанавливаются до финальной оценки вместе с преподавателем и профильным экспертом.

| ID | Требование | Критерий проверки |
|---|---|---|
| FR-01 | Принимать согласованные форматы изображений с проверкой декодирования, размеров и типа | Валидное изображение принимается; повреждённое отклоняется с понятной причиной |
| FR-02 | Выдавать маски зубов и FDI с версией модели | Сопоставление с эталонной разметкой, mAP и анализ ошибок FDI |
| FR-03 | Выдавать маску кости | Dice/IoU на независимом test; целевые пороги уточнить |
| FR-04 | Рассчитывать bone_loss_ratio по документированной геометрии | Сравнение с ручными измерениями и обработка нулевой длины корня |
| FR-05 | Применять версионированные правила к пригодным признакам | Граничные тесты и детерминированная цепочка вывода |
| FR-06 | Объяснять вывод: показатели, ID правил, версии и ограничения | Эксперт может проследить решение до исходных признаков |
| FR-07 | Возвращать «недостаточно данных» при невалидных признаках/конфликтах | Ошибочный ввод не превращается в уверенный вывод |
| FR-08 | Показывать визуализацию и передавать результат человеку для проверки | Демонстрационный сценарий и понятный статус результата |
| NFR-01 | Обеспечивать воспроизводимость | Зафиксированы код, окружение, данные, конфигурация, seed и веса |
| NFR-02 | Контролировать происхождение данных и компонентов | Для каждого материала есть источник, версия и основание использования |
| NFR-03 | Не сохранять изображения и идентификаторы пациентов в публичных логах | Проверка логов, экспорта и файлов после демонстрации |
| NFR-04 | Измерять время обработки в заданной среде | Зафиксированы оборудование, размер входа, прогрев, p50/p95 и целевой лимит |
| NFR-05 | Обозначать исследовательское назначение и ограничения | Текст виден до ввода и рядом с результатом |

Подтверждение выполнения требований хранится в матрице; наличие документа не означает реализацию функции.
